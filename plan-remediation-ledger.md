## Status Vocabulary

Allowed slice statuses:

- `NOT_STARTED`: slice has not begun.
- `IN_PROGRESS`: slice is actively being remediated.
- `BLOCKED`: slice cannot proceed safely because a blocker is documented.
- `DEFERRED`: slice is intentionally postponed or needs an explicit decision.
- `IMPLEMENTED`: code/docs changes for the slice are present but not verified.
- `VERIFIED`: required verification passed for the slice.
- `COMPLETE`: slice is implemented, verified, and closure evidence is recorded.

  them into ten normalized slices because sections 4, 10, Appendix E, and
  Appendix F contain actionable finding groups not fully enumerated as distinct
  Section 11 rows.
- `SLICE-05` is separated from the P1 operator truthfulness slice so P2/P3/P4 UI
  polish and UI-harness work do not obscure the P1 runtime-truthfulness work.
- `SLICE-08` is separated from deduplication because the roadmap distinguishes
  structural cleanup from policy/test simplification.
- `SLICE-09` keeps all physical runtime harness findings together. `plan.md`
  records missing hardware/runtime evidence but does not mark the slice as
  blocked, so its initial status remains `NOT_STARTED`.
- `SLICE-00`, `SLICE-01`, `SLICE-03`, `SLICE-04`, `SLICE-05`, `SLICE-06`,
  `SLICE-07`, and `SLICE-08` are now marked `COMPLETE` from live
  remediation evidence gathered on 2026-05-15. `SLICE-02` has implemented
  source-level audio receive and adaptive RX buffering changes but is marked
  `BLOCKED` because required local TSan evidence cannot launch on this
  platform. `SLICE-09` is also `BLOCKED` on missing physical runtime hardware,
  routes, and field evidence.
