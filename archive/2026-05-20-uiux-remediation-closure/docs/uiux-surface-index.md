# UI/UX Surface Index

Status: source audit of the current checkout on 2026-05-20.

Scope: active SwiftUI/AppKit surfaces in `Sources/open-lola-app/`,
`Sources/open-lola-app-main/`, app-shell contracts in
`Sources/OpenLolaCore/Platform/`, runtime preview code in
`Sources/OpenLolaCore/Video/RawBGRAAppKitPreviewWindow.swift`, Swift CLI entry
points in `Sources/open-lola/`, command inventory in
`Sources/OpenLolaCore/Support/Inventories/CLICommandInventory.swift`, and
Python terminal tools in `linux_connector/`.

Method: static source inspection only. The app was not launched and no live
hardware, camera, microphone, network peer, Windows LoLa host, or external
connector was exercised in this audit. `UNCLEAR` means the source did not prove
reachability, runtime wiring, or current user value.

## Main User Workflows

1. Configure a direct Mac-to-Mac session: open the app, use Devices to select
   workflow and local/remote devices, import or enter remote inventory, inspect
   Routing, then move to Session.
2. Prepare and run a direct Mac-to-Mac session: write or inspect the plan,
   arm execution, dry-run or start only when validation and evidence gates
   allow it, then validate the report and inspect Reports, Logs, Validation,
   Overview, and Packet Monitor.
3. Configure Windows LoLa mode: select Windows LoLa, set local/Windows hosts
   and media fields, inspect generated command/routing, dry-run/start through
   the Swift connector path, then validate the external connector report.
4. Monitor local preview: open Streams or the Local Preview window, enable
   local audio/video preview, confirm selected devices and permission status,
   and read preview health separately from remote stream health.
5. Diagnose readiness: use Validation for "Can I run?", Diagnostics for source
   and process/log context, Overview for next action, and Packet Monitor for
   decoded capture evidence when available.
6. Run terminal workflows: use `open-lola` for report/runtime commands and the
   Python Linux connector tools for `selftest`, `status`, `listen`, `connect`,
   packet relay, or capture decoding workflows.

## Placeholder or Stale UI

- Product/source verdict surfaces remain `PARTIAL` and report-backed by design;
  source/synthetic panels must not be promoted to field-ready `PASS`.
- Settings advertises `Command-Shift-V` for validation, but
  `validate-supervisor-report` has no keyboard shortcut in
  `NativeAppShellActionInventory`.
- External connector settings for JackTrip and UltraGrid are notice/planning
  surfaces, not app runtime launchers.
- Remote stream surfaces are report-only or plan-only until runtime evidence is
  loaded and validated.
- Remote media inventory can be manually entered/imported and may look complete
  before a generated plan or validation proves the IDs are usable.
- Vendored Opus HTML files are static upstream documentation, not an active
  Open LoLa product UI.

## Missing Screens or States

- No dedicated first-run permission/preflight screen was found for camera,
  microphone, local network, or required privacy settings; the app relies on
  runtime/system permission prompts and status text.
- No in-app file picker/browser was found for selecting report, plan, inventory,
  or capture files; paths, pasteboard JSON, and generated defaults are used.
- No live packet tailing surface was found; Packet Monitor reads decoded capture
  report data.
- No dedicated recovery wizard was found for empty device inventories,
  permission denial, invalid remote inventory, or unreachable peer hosts.
- No full keyboard-navigation or VoiceOver surface inventory was performed;
  only explicit keyboard shortcuts and the banner accessibility announcement
  bridge were inspected.
- No active web UI, XIB, storyboard, React, Vue, or Svelte app surface was found
  in the repository; vendored Opus HTML docs are static reference material.

## Highest-Risk User-Facing Areas

1. Execution and validation truthfulness: Start/Live/Validated states must stay
   gated by current report token and validated runtime evidence.
2. Stop/quit behavior while a supervisor process is running: three stop
   confirmation paths and one quit guard must remain consistent.
3. Settings while running: controls must remain locked when runtime state is
   active, and saved draft state must not silently diverge from active runtime.
4. Preview health: local preview/camera/meter success must not be confused with
   remote media or packet evidence.
5. Packet Monitor: no-data, filtered-empty, stale report, and row-error states
   must stay distinguishable.
6. External workflow modes: JackTrip/UltraGrid selection must not imply an app
   launcher exists.
7. Keyboard shortcut accuracy: the stale validation shortcut label can mislead
   users and automated documentation.

## Remaining Uncertainty

- This was a static audit. The app bundle, menu bar, windows, dialogs, settings
  scene, preview window, and packet monitor were not launched or screenshot-
  verified.
- No hardware, microphone, camera, local network peer, Windows LoLa peer,
  JackTrip peer, UltraGrid peer, `tshark`, or `scapy` runtime was exercised.
- CLI route discovery covered top-level Swift routing, command inventory, and
  selected Python terminal tools, but did not execute every command-specific
  help path.
- Accessibility coverage is incomplete beyond explicit shortcuts, tooltips/help
  found in source, and the session banner announcement bridge.
- Archived UI/UX docs were not treated as current authority; this index is based
  on live source paths listed in the scope.
