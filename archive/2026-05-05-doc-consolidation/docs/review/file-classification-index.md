## Classification Rules

Confidence levels:

- `confirmed`: directly evidenced by manifest, README, source names, or local
  documentation.
- `likely`: strongly indicated by path/name and adjacent files.
- `inferred`: reasonable classification from naming and project context.
- `unclear`: purpose needs closer reading.
- `needs human review`: requires maintainer decision or legal/compliance review.

Status labels:

- `active`: part of the current development or documentation surface.
- `partially active`: implemented/source-level but blocked on external proof.
- `stale`: superseded by current docs or reports.
- `duplicate`: overlaps another active/historical file.
- `generated`: build/tool output.
- `external/vendor`: third-party or legacy artifact.
- `internal-only`: should not be public by default.
- `public-safe`: intended publication-safe surface.
- `needs cleanup`: should be cleaned or excluded after approval.
- `unknown`: not enough evidence.

Granularity note: every non-generated top-level area, active Swift module group,
test group, documentation lane, script, root file, Windows corpus group, and
generated subtree is classified here. Repetitive generated `.build/` internals
and repeated legacy camera presets are grouped because their responsibility,
risk, and recommendation are identical at file level.
