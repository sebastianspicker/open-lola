# M11 OSC Cue Validation Report

Date: 2026-05-02  
Milestone: [M11 OSC Show-Control Probe](../milestones/M11_OSC_SHOW_CONTROL_PROBE.md)  
Status: PARTIAL

## Scope

This report validates the M11 source-level OSC cue harness: minimal OSC 1.0 cue
packet encoding/decoding, deterministic loopback cue timing, jitter report
schema, bounded external-peer/audio-baseline report writing, G08 ATEM
read-only reachability reporting, audio-impact PASS guards, fixture validation,
and synthetic smoke output. It does not validate Chataigne, Open Stage Control,
QLC+/OLA interop, real ATEM protocol/status extraction, or control traffic
while live audio is running.

## OSC Cue Contract

The report records:

- OSC peer kind, label, availability, and unavailability reason when needed;
- OSC cue address, type tags, timestamp encoding, and cue count;
- cue ID, sender timestamp, receiver timestamp, and jitter for each cue;
- jitter p50/p95/p99/max;
- audio baseline report ID when the operator supplies one;
- baseline and cue-loop audio callback p99/max, playout target, underruns, and
  hidden audio-impact flag;
- PASS, FAIL, or PARTIAL verdict.

PASS reports require an available local loopback peer, matching cue count,
valid OSC cue packet shape, unchanged audio callback p99/max, unchanged playout
target, zero underruns, and no hidden audio impact. External-peer interop is
recorded separately before it can close the milestone.

## ATEM Read-Only Contract

The ATEM report records:

- host/IP, control port, protocol label, network interface, and
  same-network-as-audio flag;
- model, firmware, program source, preview source, tally, and audio mixer state
  when available;
- connection health, bounded connection-attempt duration, and error message;
- `armedCommandsAllowed=false`;
- PASS, FAIL, or PARTIAL verdict.

PASS reports require connected health, network evidence, non-placeholder ATEM
status fields, and no armed commands. Generic builds do not link the Blackmagic
SDK.

## Deferred Runtime Evidence

M11 cannot be marked PASS until real reports exist for:

- local UDP OSC loopback with an accepted audio baseline active;
- cue-loop run with an accepted M05/M06 or M10 audio baseline;
- Chataigne interop;
- Open Stage Control fallback interop if Chataigne is unavailable;
- real ATEM protocol or SDK-backed read-only model/firmware/program/preview,
  tally, and audio mixer evidence;
- QLC+/OLA OSC behavior if lighting control depends on it;
- proof that cue traffic does not change callback p99/max, playout target, or
  underrun count.
